# Fast hybrid truecasing

Восстанови естественный регистр английского текста в записях `target`. Приоритет — личные имена, фамилии, прозвища и географические названия. Изменяй регистр только при достаточном подтверждении.

## Вход

```json
{
  "context_before": [{"id": 1, "text": "..."}],
  "target": [{"id": 2, "text": "..."}],
  "context_after": [{"id": 3, "text": "..."}],
  "entity_cache": [
    {"form": "gauntlet", "canonical": "Gauntlet", "type": "person_alias", "ambiguous": true}
  ],
  "heading_cache": [
    {"form": "a grim gauntlet", "canonical": "A Grim Gauntlet"}
  ],
  "candidate_hints": [
    {"form": "rook", "type": "person", "source": "ner"}
  ]
}
```

`entity_cache`, `heading_cache` и `candidate_hints` необязательны. Если они отсутствуют, работай только с текстом и локальным контекстом.

- `context_before` и `context_after` используй только для понимания `target`. Не изменяй и не возвращай их.
- `entity_cache` содержит ранее подтверждённые формы для текущей книги или сюжетного сегмента.
- `heading_cache` содержит подтверждённые заголовки.
- `candidate_hints` содержит неподтверждённые кандидаты предварительной обработки.
- Первый алфавитный символ каждой записи и отдельное местоимение `i` уже нормализованы. Не обрабатывай их повторно. Исправляй только начала новых предложений внутри записи.

## Правила

### Имена и географические названия

Найди в `target` личные имена, фамилии, прозвища, псевдонимы, сокращённые формы, географические названия и их притяжательные формы.

Считай кандидата подтверждённым, если выполняется хотя бы одно условие:

- рядом указаны имя, фамилия, титул или обращение;
- слово называет участника действия, говорящего, адресата или конкретное место;
- конструкции вроде `X said`, `asked X`, `Mr. X` или полное имя связывают форму с одной сущностью;
- соседний контекст однозначно связывает форму с уже подтверждённой сущностью;
- это притяжательная форма подтверждённого собственного имени.

Сначала используй текст самой записи. Соседние записи используй только для разрешения неоднозначности.

### Кэш, кандидаты и распространение

- Форму из `entity_cache` с `ambiguous: false` разрешено автоматически применять в пределах текущей книги или сюжетного сегмента.
- Форму с `ambiguous: true` проверяй при каждом употреблении.
- `heading_cache` используй для определения текста и границы повторяющегося заголовка.
- `candidate_hints`, NER, частота и совпадение со словарём являются только подсказками, а не доказательством.
- Не распространяй автоматически форму, которая может быть обычным словом или местоимением.
- Не считай слово именем только потому, что такое имя существует.

### Структура текста

- Исправляй начала новых предложений внутри записи по терминальной пунктуации и кавычкам.
- Распознавай заголовки вида `Episode <number>`, `Chapter <number>` и `Book <number>`.
- Определяй границу заголовка и основного текста по `heading_cache`, оглавлению, повторяющемуся названию или локальному контексту.
- Применяй естественный английский title case к заголовку и прописную букву к первому слову основного текста.
- Не добавляй отсутствующие двоеточия, точки или другие разделители.

Пример:

```text
Episode 29 A Grim Gauntlet With their booted feet drumming against the dirt Rook guided their way through town .
```

### Вторичные категории

- Организации, группы и учреждения исправляй только при явном подтверждении контекстом или локальным кэшем.
- Названия произведений исправляй только тогда, когда они явно представлены как название, встречаются в оглавлении или подтверждены локальным кэшем.
- Аббревиатуры и акронимы исправляй только при известной канонической форме из контекста или локального кэша.
- Титул, должность или обращение капитализируй, если они связаны с именем или заменяют имя в прямом обращении.
- Contractions с потерянным апострофом обрабатывай отдельно от имён и только при однозначном грамматическом контексте. Не добавляй апостроф.

## Не обрабатывать автоматически

- Произвольные фразы, похожие на названия только из-за положения в тексте.
- Неизвестные аббревиатуры без подтверждённой канонической формы.
- Обычные существительные, глаголы, прилагательные, местоимения и служебные слова, даже если они совпадают с именем.
- Неоднозначные формы вроде `will`, `may`, `rose`, `rook`, `crash`, `ashes` или `gauntlet`.
- Обычные титулы и должности, не связанные с именем и не заменяющие имя в прямом обращении.
- Данные из интернета или других внешних источников.

## Разрешённая предварительная обработка

Внешний пайплайн может использовать regex для структуры и проверки результата, NER для поиска кандидатов, локальные словари и кэши, частоты, повторяющиеся конструкции и консервативное распространение подтверждённых однозначных форм внутри одной книги.

Используй результаты предварительной обработки только как подсказки. Не имитируй запуск regex, NER или других инструментов, если их результаты не предоставлены во входе.

## Ограничения

- Изменяй только регистр букв.
- Не меняй символы, написание слов, пунктуацию, пробелы, порядок или длину текста.
- Исправленный текст должен иметь исходную длину и совпадать с исходным при сравнении без учёта регистра.
- Не выводи кандидатов, объяснения или комментарии.

## Ответ

Верни только записи из `target`, в которых был изменён регистр:

```json
{
  "records": [
    {"id": 2, "text": "Corrected full text"}
  ],
  "needs_context": []
}
```

- `text` — полный исправленный текст записи.
- Неизменённые записи не включай в `records`.
- Неоднозначный кандидат оставь без изменений и добавь `id` записи в `needs_context`.
- Если в той же записи есть уверенные исправления, включи её в `records`. Один `id` может одновременно присутствовать в `records` и `needs_context`.
- Если уверенных исправлений нет, верни `id` только в `needs_context`.
- Возвращай только валидный JSON указанной структуры.
