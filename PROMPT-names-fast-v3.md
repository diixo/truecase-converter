# Candidate-first truecase resolver

Определи правильный регистр только для новых или неоднозначных кандидатов английского текста. Не переписывай полные записи. Верни решения, которые внешний пайплайн применит к исходному JSONL.

## Предусловия

До вызова модели внешний пайплайн уже:

- исправил первый алфавитный символ записи, начала предложений и реплик, отдельное `i` и однозначные contractions;
- применил подтверждённые формы из `entity_cache` с `ambiguous: false`;
- выделил неизвестные кандидаты и собрал для каждого не более 1–3 наиболее информативных примеров;
- отправил отдельно только те употребления неоднозначных форм, которые требуют контекстного решения.

Не проверяй эти операции повторно.

## Вход

```json
{
  "candidates": [
    {
      "form": "mensak",
      "hint_type": "person",
      "frequency": 50,
      "examples": [
        {
          "id": 11396843,
          "text": "You can call me mensak - most other folk do .",
          "before": "...",
          "after": "..."
        }
      ]
    }
  ],
  "ambiguous_occurrences": [
    {
      "id": 11393343,
      "form": "mist",
      "text": "Mist looked at him .",
      "before": "...",
      "after": "..."
    }
  ],
  "heading_candidates": [
    {
      "id": 11390127,
      "text": "Chapter forty-seven sarssen sat down .",
      "known_prefix": "chapter forty-seven"
    }
  ],
  "entity_cache": [
    {
      "form": "sarssen",
      "canonical": "Sarssen",
      "type": "person",
      "ambiguous": false
    }
  ],
  "negative_cache": ["rose", "will"],
  "heading_cache": [
    {
      "form": "chapter forty-seven",
      "canonical": "Chapter Forty-Seven"
    }
  ]
}
```

Обязателен только массив `candidates`. Остальные поля могут отсутствовать.

- `examples` — подтверждающий контекст, а не список всех употреблений.
- `frequency`, `hint_type` и результаты NER являются только подсказками.
- `entity_cache` используй только для связи кандидата с уже известными сущностями. Не возвращай решения для кэша повторно.
- `negative_cache` содержит уже отклонённые обычные слова. Не анализируй их повторно, если новый контекст явно не доказывает употребление как имени.
- `ambiguous_occurrences` решай отдельно по `id`; не распространяй одно решение на все употребления формы.
- `heading_candidates` содержит только заголовки, которые не удалось решить детерминированно.

## Решения по кандидатам

Для каждого элемента `candidates` выбери ровно одно решение:

- `entity` — форма является однозначным собственным именем в пределах текущей книги или сюжетного сегмента;
- `common` — обычное слово, ложный NER-кандидат или неподтверждённая сущность;
- `ambiguous` — форма может быть и именем, и обычным словом, поэтому требует решений по отдельным употреблениям;
- `needs_context` — предоставленного текста недостаточно.

Подтверждай `entity`, если контекст показывает хотя бы одно из следующего:

- это участник действия, говорящий, адресат или конкретное место;
- рядом есть имя, титул, должность, обращение или конструкция вроде `X said`, `asked X`, `called X`, `named X`;
- несколько примеров однозначно относятся к одной уже известной сущности;
- это географическое название, демоним или притяжательная форма подтверждённого имени.

Не подтверждай форму только из-за NER, частоты, позиции в предложении или существования такого имени в языке.

Допустимые типы: `person`, `person_alias`, `place`, `demonym`, `organization`, `work`, `title`, `acronym`, `other_proper`.

## Контекстные решения

Для каждого элемента `ambiguous_occurrences` выбери:

- `capitalize` — в этой записи форма является собственным именем или заменяющим имя обращением;
- `keep` — в этой записи форма употреблена как обычное слово;
- `needs_context` — контекста недостаточно.

Титулы и должности капитализируй только рядом с именем или в прямом обращении. Неоднозначные формы вроде `will`, `may`, `rose`, `rook`, `mist`, `choice`, `lute`, `crash`, `ashes` и `gauntlet` никогда не распространяй глобально без однозначного подтверждения.

## Заголовки

Для `heading_candidates` верни только исправленный регистр подтверждённого префикса заголовка. Используй естественный английский title case для `Chapter`, `Episode`, `Book` и названия главы. Не добавляй разделители и не включай основной текст записи в `canonical_prefix`.

Если граница заголовка неизвестна, используй `needs_context`.

## Ограничения

- Разрешено изменять только регистр существующих букв.
- Нельзя менять написание, символы, пунктуацию, пробелы, порядок или длину.
- Нельзя добавлять потерянные апострофы.
- Не используй интернет или внешние знания.
- Не возвращай исправленные полные записи, объяснения или комментарии.

## Ответ

Верни только валидный JSON:

```json
{
  "candidate_decisions": [
    {
      "form": "mensak",
      "decision": "entity",
      "canonical": "Mensak",
      "type": "person"
    },
    {
      "form": "rose",
      "decision": "common"
    }
  ],
  "occurrence_decisions": [
    {
      "id": 11393343,
      "form": "mist",
      "decision": "capitalize",
      "canonical": "Mist"
    }
  ],
  "heading_decisions": [
    {
      "id": 11390127,
      "decision": "confirmed",
      "canonical_prefix": "Chapter Forty-Seven"
    }
  ],
  "needs_context": []
}
```

Правила ответа:

- `canonical` обязателен только для `entity` и `capitalize`.
- `type` обязателен только для `entity`.
- Для `common`, `ambiguous` и `keep` не добавляй `canonical`.
- Кандидаты с решением `needs_context` также добавляй в `needs_context` как `{"form": "...", "ids": [...]}`.
- Неразрешённый заголовок добавляй как `{"id": 123, "kind": "heading"}`.
- Сохраняй исходную форму в поле `form`; не объединяй разные написания без явного подтверждения.
