### Algorithm

Сейчас я использую двухэтапный алгоритм: сначала контекстно определяю, что именно должно иметь верхний регистр, потом Python только механически применяет эти решения и проверяет, что кроме регистра ничего не изменилось.

Алгоритм сейчас такой:

Определяю границы книг/фрагментов.
Смотрю начало файла, несколько участков по всей длине и места вроде:

- the end
- chapter one
- chapter 1
- prologue
- резкая смена персонажей/сюжета

Если начинается новая книга, предыдущий контекст имён сбрасывается. То есть имя из одной книги не должно автоматически капитализироваться в другой.

По контексту определяю сущности внутри каждого фрагмента.
Например из:

travis is standing in front of me...
before they can let you see tommi

делаю вывод, что travis и tommi — имена.

Или:

mr. locke

→ Mr. Locke.

Это решение принимается именно по тексту и соседнему контексту, а не правилом вроде «редкое слово = имя».

## 3
Формирую для конкретного фрагмента карту канонического регистра, например условно:
```python
{
    "tommi": "Tommi",
    "travis": "Travis",
    "sig locke": "Sig Locke",
    "bill lemmon": "Bill Lemmon",
    "mr. locke": "Mr. Locke"
}
```

Это не глобальный словарь на весь BookCorpus. Он относится к текущей книге/фрагменту.

## 4
Python применяет уже принятые решения.
Он не решает, является ли tommi именем. Он только заменяет:
```python
tommi -> Tommi
sig locke -> Sig Locke
```

по всему соответствующему фрагменту.

## 5
Отдельно механически восстанавливаю очевидный регистр:
- начало предложения:
i went home. → I went home.
- отдельное местоимение:
i → I
- заголовочные маркеры:
chapter → Chapter
prologue → Prologue
part → Part
epilogue → Epilogue
- дни недели и месяцы:
monday → Monday
january → January

## 6
На строке, где заканчивается одна книга и тут же начинается другая, например:
the end chapter one may hardy ...

я могу временно использовать обе карты сущностей только для этой строки, чтобы корректно восстановить и конец предыдущего текста, и начало следующего.

## 7 
После конвертации выполняется строгая проверка:
original.lower() == converted.lower()

То есть разрешено изменить только регистр букв. Также проверяются:

- те же 10 000 записей;
- те же id;
- те же JSON-ключи;
- никакого изменения пунктуации, пробелов, слов или символов.

Но есть важный момент: **сейчас это не полноценный truecasing каждого слова через динамическое 5–8-предложенческое окно**. Практически я сначала анализирую фрагменты и составляю контекстно подтверждённый набор сущностей, а затем распространяю их регистр внутри книги. Поэтому основная потенциальная слабость текущего метода — **можно пропустить редкое имя/название, которое встретилось один-два раза и не попало в составленную карту**.

То есть текущая схема в сокращённом виде:

```text
текст
  ↓
определение границ книг
  ↓
контекстный анализ персонажей / мест / организаций
  ↓
entity → Canonical Case
  ↓
механическое применение по соответствующему фрагменту
  ↓
sentence-start + I + headings + dates
  ↓
проверка: изменился только case
```

Иными словами, решение о смысле делает контекстный анализ, Python здесь используется как детерминированный исполнитель этих решений, а не как NER/эвристический truecaser.
